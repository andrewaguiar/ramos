Summary

Kernel — the implicit, always-in-scope module of built-ins.

Module documentation

Kernel — the implicit, always-in-scope module of built-ins.

Kernel is auto-imported into every scope, so its functions are the only ones you call bare — print(x) is sugar for Kernel.print(x), and no alias is ever needed for it. Every other module must be named or aliased.

It is the seam between Ramos code and the host runtime. Its functions have no Ramos bodies: each delegates to a native handler via native(str, args), which the interpreter intercepts and dispatches. As a result Kernel collects the primitives that can't reasonably be expressed in Ramos itself:

  • console I/O — print, println, new_line, read, read_all, read_password, eprint, eprintln
  • process — get_args, get_arg, get_env, sleep, exit
  • time — now (wall clock), monotonic (elapsed)
  • randomness — random, random_int (not cryptographic)
  • collection ops — size (List/Tuple/Map), at (List/Tuple), to_list, is_empty (also strings)
  • conversions — to_string (display), inspect (debug), to_integer, to_float, type_of (there is deliberately no to_symbol — see below)
  • calling — apply(f, args), module_apply(m, fn_name, args) (see the Module module)
  • actors — start_actor, call_actor, cast_actor, list_actors, actor_stats, is_actor_started, stop_actor
  • diagnostics — current_stacktrace
  • errors — error(type, message) (with a stacktrace) and exception(type, message) (without, for business logic) — see "Error handling" in the README
  • type predicates — is_integer, is_string, is_list, …
  • truthiness — is_truthy (pure Ramos, no native; not inverts it)

Because Kernel is always in scope, these read as language-level built-ins rather than library calls:

print("hi")
n = size([1, 2, 3])
cond
  is_tuple(value) -> ...

Conventions:

  • out-of-range at returns nil.
  • the is_* predicates mirror the built-in type modules listed in the README's Types table (plus is_lambda for anonymous functions).
  • there is no to_symbol, by design. A symbol lives for as long as the program does, so building one from runtime data — a request field, a line of input — is an unbounded leak. Symbols are written as literals (:ok), which keeps the set of them finite and visible in the source. To carry runtime text, use a String; to branch on it, match the string and yield a literal symbol.

function native(str, args) ¶

Invokes a host-provided (native) function by name.

str is the name of the native function to call, and args is a list of arguments to forward to it. This function has no Ramos body — the interpreter intercepts the call and dispatches it to the corresponding native handler in the host runtime.

native("print", ["hello"])   # handled by the interpreter
str
the name of the native handler to invoke
args
a List of arguments forwarded to the handler

Returns: whatever the native handler returns

function exit(code) ¶

Ends the program with code as its exit status — 0 for success, any other value for failure. Nothing after the call runs.

Output written with print is flushed on the way out, so a program can print its result and exit in the next breath without losing it.

exit(0)                # success
exit(1)                # failure
code
the process exit status

Returns: never returns

function now() ¶

The wall-clock time as milliseconds since the Unix epoch.

This is the clock to timestamp with. It can jump backwards when the system clock is adjusted, so measure elapsed time with monotonic.

started = now()

Returns: an Integer — milliseconds since 1970-01-01 UTC

function monotonic() ¶

Milliseconds from a fixed point in the program's life. The value only ever moves forward, which is what makes it the right clock for measuring how long something took.

The origin is arbitrary, so a single reading means nothing on its own — only the difference between two does.

started = monotonic()
# ... work ...
elapsed = monotonic() - started

Returns: an Integer — milliseconds since an arbitrary fixed point

function random() ¶

A random Float in [0.0, 1.0) — zero is possible, one is not.

Not cryptographic: this is for sampling, shuffling and test data, never for secrets or tokens.

chance = random()

Returns: a Float in [0.0, 1.0)

function random_int(low, high) ¶

function apply(f, args) ¶

Calls the lambda f with args, a list of its arguments. Use it when the arity is not known where the call is written — otherwise call f directly.

Like native, this function has no Ramos body: the interpreter intercepts the call, because running a lambda needs the evaluator and a native handler cannot reach back into it. Also like native, it is answered for the bare call apply(...), not for Kernel.apply(...).

apply(do x, y -> x + y, [1, 2])   # == 3
apply(do -> 42, [])               # == 42
f
the lambda to call
args
a List of the arguments to pass

Returns: whatever f returns

function module_apply(m, fn_name, args) ¶

Resolves fn_name on module m and calls it with args, a list. Module.apply is the client-side name for this — prefer it.

Enforces the same helper visibility a written m.fn_name(...) call would: a private function is reachable only from inside its own module, so this cannot reach around that rule from the outside.

Like apply, this function has no Ramos body: the interpreter intercepts the call, since resolving fn_name and running it needs the evaluator. Also like apply, it is answered for the bare call module_apply(...), not for Kernel.module_apply(...).

module_apply(Integer, "abs", [-7])   # == 7
m
the module to call a function on
fn_name
the function's name, as a String
args
a List of the arguments to pass

Returns: whatever the resolved function returns

function start_actor(id, actor_module, initial_state, config) ¶

Starts an actor under id, handled by module — which must implement the Actor trait — holding initial_state. config is fixed for the actor's lifetime and passed to every call and cast.

The id is what identifies a running actor, so one module can back many of them, each with its own state. Starting the same id twice is an error.

Like apply, this function has no Ramos body: the interpreter intercepts the call, because dispatching a message runs Ramos code and a native handler cannot reach back into the evaluator. Also like apply, it is answered for the bare call start_actor(...), not Kernel.start_actor(...).

start_actor(:global, Global, {}, {})
id
the name to register the actor under, conventionally a symbol
actor_module
the module implementing Actor
initial_state
the state the actor starts with
config
fixed configuration handed to every callback

Returns: :ok

function call_actor(id, actor_module, op, args) ¶

Sends op to the actor registered under id and waits for the reply. The module's call(f, args, state, config) handles it and returns a (reply, new_state) tuple: the reply comes back here, and new_state is what the actor holds from then on.

Any messages sent earlier with cast_actor are handled first, in the order they were sent, so a call always sees everything sent before it.

Has no Ramos body, for the reason given on start_actor.

call_actor(:global, Global, :get, ["key"])
id
the actor's id, as given to start_actor
actor_module
the module handling that actor
op
the operation, conventionally a symbol such as :get
args
a List of arguments for the operation

Returns: whatever the handler put in the reply position

function cast_actor(id, actor_module, op, args) ¶

Sends op to the actor registered under id without waiting for it to be handled, and returns :ok at once. The message goes on the actor's mailbox and runs later: before the next call_actor on that actor, or when the program ends, whichever comes first.

The module's cast(f, args, state, config) handles it and returns only the new state — a cast has no reply to send anywhere. Unless the module defines its own, the Actor trait's default runs call and discards the reply.

Because the handler runs later, a failure inside it surfaces later too: at the drain, after the statement that sent the message.

Has no Ramos body, for the reason given on start_actor.

cast_actor(:global, Global, :clear, ["key"])
id
the actor's id, as given to start_actor
actor_module
the module handling that actor
op
the operation, conventionally a symbol
args
a List of arguments for the operation

Returns: :ok, immediately

function list_actors() ¶

Every running actor as an (id, module) pair, sorted by id so the order is stable from one call to the next. The id is the value it was started with, and the module is the module itself — so a pair can be handed straight to call_actor or cast_actor.

Has no Ramos body, for the reason given on start_actor.

list_actors()   # == []
[(id, mod) | _] = list_actors()
call_actor(id, mod, :ping, [])

Returns: a List of (id, module) tuples

function actor_stats(id) ¶

What is known about one running actor, as a Map:

  • id — the id it was started with
  • module — the name of the module handling it, as a String
  • calls — how many call_actor messages have been sent to it
  • casts — how many cast_actor messages have been sent to it
  • pending — casts sent whose outcome has not been collected yet
  • alive — whether its thread is still running

calls and casts count messages sent. A cast is asynchronous, so it may still be running: pending is the part not accounted for yet, and drops to zero once the handler has finished and its result been collected.

Has no Ramos body, for the reason given on start_actor.

actor_stats(:global)
id
the actor's id, as given to start_actor

Returns: a Map describing the actor

function is_actor_started(id) ¶

Whether id names a running actor. False for an id that was never started, and for one that has been stopped.

Has no Ramos body, for the reason given on start_actor.

is_actor_started(:nobody)   # == false
id
the id to test

Returns: true when an actor is running under id

function stop_actor(id) ¶

Lets the actor finish everything already sent to it, then ends its thread and forgets the id. Nothing in flight is discarded: the stop is queued behind the messages already in the mailbox.

Afterwards the id is free, so start_actor may reuse it. Sending to a stopped actor is an error, the same as sending to one never started.

Has no Ramos body, for the reason given on start_actor.

stop_actor(:global)
id
the actor's id, as given to start_actor

Returns: :ok

function current_stacktrace() ¶

Returns the current call stacktrace — the chain of Ramos calls leading to this point — as a list of (file, line) tuples, most recent call first and the outermost caller (main, or wherever the trail runs out) last.

A self-recursive tail call is not a frame of its own: it loops in constant space rather than recursing, so however many times it has looped, it still contributes exactly one entry — the line the loop is currently at.

print(current_stacktrace())

Returns: a List of (file, line) tuples, most recent call first

function error(type, message) ¶

Builds the standard error tuple: (:error, (type, message, stacktrace)). This — together with exception, its stackless twin — is the one way Ramos code reports failure: there is no raise and no catch. A fallible function returns (:ok, value) on success and whatever this builds on failure, and the caller reads either with case like any other value.

type is a lowercase symbol naming what went wrong — the part code matches on. message is for the human reading the output: a String, or a struct when a plain string is not enough detail. The stacktrace is current_stacktrace(), captured where error is called, so a failure carries where it came from without a caller having to ask for it.

Reach for error where that trace earns its cost — a lower-level or unexpected failure worth tracing back. Ordinary business-rule failures (a bad request, a declined charge) happen too often and too predictably for a trace to be useful — use exception for those.

built = error(:insufficient_funds, "balance is too low")
(:error, (type, message, _)) = built
(type, message)   # == (:insufficient_funds, "balance is too low")
type
a symbol naming what went wrong
message
a String, or a struct carrying further detail

Returns: (:error, (type, message, stacktrace))

function exception(type, message) ¶

Builds the business-logic error tuple: (:error, (type, message)) — the same shape as error, minus the stacktrace.

An expected failure — a bad request, a declined charge, a value that fails validation — happens in the ordinary run of a program and is handled a line or two away, so a stacktrace would only be noise. Use exception for those, and save error (which captures one) for a failure worth tracing back to where it happened.

exception(:insufficient_funds, "balance is too low")
# == (:error, (:insufficient_funds, "balance is too low"))
type
a symbol naming what went wrong
message
a String, or a struct carrying further detail

Returns: (:error, (type, message))

function inspect(value) ¶

The debug rendering of value: strings keep their quotes and symbols their colon, so a value reads back as the source that would build it. This is what the REPL prints and what error messages quote.

to_string gives the display form instead, which renders a string bare. The two differ only at the top level — a string nested inside a list is quoted either way.

inspect("hi")        # == "\"hi\""
to_string("hi")      # == "hi"
inspect([1, "two"])  # == "[1, \"two\"]"
inspect(:ok)         # == ":ok"
value
the value to render

Returns: a String — the debug rendering

function type_of(value) ¶

The module value belongs to — the one the README's Types table lists.

A String rather than a Symbol: module names are CamelCase and symbol names are snake_case, so :Integer is not a symbol you could write, and a value you cannot write is a poor thing to compare against.

type_of(42)        # == "Integer"
type_of(3.14)      # == "Float"
type_of("hi")      # == "String"
type_of([1, 2])    # == "List"
type_of(nil)       # == "Nil"
value
the value to inspect

Returns: a String naming the value's module

function is_empty(value) ¶

Whether value holds nothing — an empty list, map, tuple or string.

size deliberately rejects strings (they count code points, not elements), so this is the one question that spans all four.

is_empty([])       # == true
is_empty({})       # == true
is_empty("")       # == true
is_empty([1])      # == false
is_empty("hi")     # == false
value
a list, map, tuple or string

Returns: true when it holds no elements or characters

function is_truthy(value) ¶

Whether value counts as true in a condition. Only false and nil are falsy — every other value, including 0, "" and [], is truthy. This is the rule if, cond, and, or and not all use.

There is no native behind this one: a cond arm already tests a value for truthiness, so the function is that rule written down.

is_truthy(0)       # == true
is_truthy("")      # == true
is_truthy([])      # == true
is_truthy(nil)     # == false
is_truthy(false)   # == false
value
the value to test

Returns: true when value is truthy, false when it is false or nil
