Module documentation

Config — the environment's .env file, read once and answered from memory.

One actor named :config holds the settings for this run. start picks the file from the APP_ENV environment variable, reads it, parses it, and hands the result to the actor; from then on get is the only operation. Nothing writes — the actor is read-only, so what a program sees at the end of a run is what it saw at the start.

The examples here and below are written against this .env:

# ramos doctest setup
settings =
  """
    [database]
    host = "db.internal"
    port = 5432
  """
File.write(".env", settings)

Read back, that is:

Config.start()                   # == :ok
Config.get("database", "host")   # == "db.internal"
Config.get("database", "port")   # == "5432"
Config.get("database", "user")   # == nil

Which file. APP_ENV names the environment and the file is .env followed by its downcased name — APP_ENV=PROD reads .env.prod, APP_ENV=staging reads .env.staging. With APP_ENV unset or empty the plain .env is read. path() reports the choice without starting anything. The path is relative, so it resolves against the working directory the program was run from.

The format is TOML, of the subset a settings file actually uses: [section] headers, key = value pairs, # comments, blank lines. Every value comes back as a String — port = 5432 reads as "5432" — because the file cannot say what a value was meant to be and guessing would make get return a different type for the same key on a different deploy. Use to_integer on the way out when you need a number.

Quotes around a value are stripped, single or double. An unquoted value ends at a trailing # comment; a quoted one does not, so a # inside quotes is part of the value. A key that appears twice takes its last value, and a key written before the first [section] has no section to be asked for, so it is skipped.

Missing files are not an error to get. start reports an unreadable file as (:error, reason) in File's vocabulary, so the caller decides whether a run without config is fatal:

case Config.start()
  :ok -> run()
  (:error, :enoent) -> run_with_defaults()

Config is an ordinary Actor implementation, so list_actors, actor_stats(:config) and stop_actor(:config) all work on it. For state that changes as a program runs, see Global.

fn start() ¶

Read the environment's file and start the :config actor on it. Call it once, before anything reads; starting it twice is an error.

Reading happens here rather than inside the actor, so a missing or unreadable file surfaces at the call that started it.

`File`'s reasons, so `:enoent` is "no such file"
Config.start()   # == :ok
Config.get("database", "host")   # == "db.internal"

fn path() ¶

The file start will read, chosen from APP_ENV: .env.<downcased> when it is set, and .env when it is not. Reads nothing itself.

With APP_ENV=PROD this reads .env.prod; unset, as here, it is .env:

Config.path()   # == ".env"
