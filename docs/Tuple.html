Tuple — operations on fixed-size, immutable tuples.

A tuple in Ramos is a small, fixed-arity record written with parentheses, e.g. (1, 2) or (:ok, value). Tuples are immutable and heterogeneous, and their arity is fixed at creation — unlike lists, you cannot "cons" onto a tuple or recurse over its elements generically.

Kernel already reads tuples — size(t), at(t, i) and to_list(t) all work on one — so this module does not repeat them. What is left is the writer set, the constructor from_list, and the conveniences built on top. Reading by position is at, or destructuring when the arity is known:

result = (:ok, 42)
at(result, 0)               # == :ok
(status, value) = result    # status == :ok, value == 42
to_list(("a", "b", "c"))    # == ["a", "b", "c"]

Tagged tuples (:ok, value) / (:error, reason) are the idiomatic result type for fallible operations — see the README's pattern-matching section.

Conventions:

  • indexes are zero-based.
  • out-of-range access returns nil; out-of-range put returns the tuple unchanged (tuples cannot change arity).

fn from_list(list) ¶

A tuple of the list's elements, in order — the inverse of Kernel's to_list. This is the only way to build a tuple whose arity is not written in the source.

Tuple.from_list([1, 2, 3])   # == (1, 2, 3)
Tuple.from_list([:ok, 42])   # == (:ok, 42)

An empty list yields the zero-arity tuple, which has no literal form — () is not something you can write.

list
the list to convert

Returns: a Tuple of the list's elements, in order

fn to_map(tuple) ¶

Converts a tuple of (key, value) pairs into a map. Later pairs win on duplicate keys.

Tuple.to_map(((:a, 1), (:b, 2)))   # == {a: 1, b: 2}
tuple
a tuple whose elements are (key, value) pair tuples

Returns: a Map built from the pairs, later pairs winning on duplicate keys
