DateTime

Summary

DateTime — a NaiveDateTime plus a fixed offset from UTC, so it names a precise instant rather than just a wall-clock reading.

Module documentation

DateTime — a NaiveDateTime plus a fixed offset from UTC, so it names a precise instant rather than just a wall-clock reading.

There is no time zone database here (no dependency ships one) — an offset_minutes is a plain number, like -300 for UTC-5 or 330 for UTC+5:30, not a zone name that shifts with daylight saving. The fields (year..millisecond) are the local reading at that offset:

utc = DateTime.now()
ny = DateTime.now_at(-300)
utc.offset_minutes   # == 0
ny.offset_minutes    # == -300

Two DateTimes at different offsets can still name the same instant — compare and diff_millis account for the offset, so they agree with what a clock actually measures, not just the printed fields:

a = DateTime.new(2024, 1, 1, 12, 0, 0, 0)     # noon UTC
b = DateTime.new(2024, 1, 1, 7, 0, 0, -300)   # 07:00 at UTC-5 — the same instant
DateTime.compare(a, b)   # == 0

== does not know this — it compares fields structurally like any other struct, so a == b above is false even though they name one instant. Convert with with_offset (or to_utc) before comparing fields directly.

now_in and in_time_zone take a TimeZone (a name plus a fixed offset) rather than a bare number, when a name is worth carrying:

ist = TimeZone.fixed("IST", 330)
DateTime.now_in(ist).offset_minutes   # == 330

Conventions:

  • compare orders by instant (the UTC equivalent), not by the printed local fields.
  • to_iso renders the offset as Z for UTC or ±HH:MM otherwise (via TimeZone.offset_text), and parse reads the same shape back.
  • see NaiveDateTime for the zone-free version of this shape, Date for the calendar day alone, and TimeZone for the named-offset type.

function new(year, month, day, hour, minute, second, offset_minutes) ¶

Builds a DateTime from local fields at offset_minutes from UTC, with millisecond: 0. Every field past year normalizes when it overflows or underflows its natural range, the same way Date.new's day does.

DateTime.new(2024, 2, 9, 13, 45, 30, 0)
# == DateTime{year: 2024, month: 2, day: 9, hour: 13, minute: 45, second: 30, millisecond: 0, offset_minutes: 0}
year
the calendar year, any integer
month
the month, 1..12
day
the day of month; out-of-range values roll over
hour
the hour, 0..23; out-of-range values roll over
minute
the minute, 0..59; out-of-range values roll over
second
the second, 0..59; out-of-range values roll over
offset_minutes
the offset from UTC, in minutes (e.g. -300 for UTC-5)

Returns: a new DateTime

function from_naive(naive, offset_minutes) ¶

Tags a NaiveDateTime's fields as the local time at offset_minutes — a relabeling, not a conversion: the fields are copied as they are.

DateTime.from_naive(NaiveDateTime{year: 2024, month: 2, day: 9, hour: 13}, -300)
# == DateTime{year: 2024, month: 2, day: 9, hour: 13, minute: 0, second: 0, millisecond: 0, offset_minutes: -300}
naive
the wall-clock reading to tag
offset_minutes
the offset from UTC those fields are read at

Returns: a DateTime with naive's fields and the given offset

function parse(text) ¶

Parses "YYYY-MM-DDTHH:MM:SS±HH:MM" (or a trailing "Z" for UTC) — either a T or a plain space between the date and the time, as to_iso renders or as the U"..." sigil is written. The seconds' fractional part is optional and any number of digits (padded or truncated to milliseconds), the same as NaiveDateTime.parse.

DateTime.parse("2024-02-09T13:45:30.500Z")
# == DateTime{year: 2024, month: 2, day: 9, hour: 13, minute: 45, second: 30, millisecond: 500, offset_minutes: 0}
DateTime.parse("2024-02-09 13:45:30.123456-05:00")
# == DateTime{year: 2024, month: 2, day: 9, hour: 13, minute: 45, second: 30, millisecond: 123, offset_minutes: -300}
text
a date-time in "YYYY-MM-DD[T ]HH:MM:SS[.fraction](Z|±HH:MM)" form

Returns: the corresponding DateTime

function compare(self, other) ¶

Orders two date-times by the instant they name (their UTC equivalent), as -1, 0 or 1 — not by their printed local fields, so two DateTimes at different offsets compare correctly.

DateTime.compare(DateTime{hour: 1}, DateTime{hour: 2})                        # == -1
DateTime.compare(DateTime{hour: 12}, DateTime{hour: 7, offset_minutes: -300})  # == 0
self
the first date-time
other
the second date-time

Returns: -1 when self is earlier, 1 when later, 0 when equal

function diff_millis(self, other) ¶

The number of milliseconds from the instant other names to the one self names — positive when self is later, negative when earlier.

DateTime.diff_millis(DateTime{second: 10}, DateTime{second: 1})   # == 9000
self
the later (or earlier) date-time
other
the date-time to measure from

Returns: an Integer millisecond count
