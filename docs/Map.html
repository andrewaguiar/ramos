Module documentation

Map — operations on key/value maps.

{name: "andrew"} is a Map. A key is an Integer, a String or a Symbol — nothing else, so every map can be written as a literal: {name: 1} (the bare-name shorthand for the symbol :name), {"host": 1} and {8080: 1}. Putting a key of any other type is an error.

Maps are immutable and insertion-ordered: put on an existing key replaces its value in place, a new key is appended, and every operation returns a new map rather than changing the one it was given.

config = {host: "localhost", port: 8080}
Map.get(config, :host, "?")   # == "localhost"

The basics — put, get, delete, has_key, keys, entries, from_list — are host primitives. Everything that takes a lambda is written in Ramos on top of them, because a native cannot call back into the interpreter to run one.

Kernel already covers the rest, so this module does not repeat it: size(m) counts the pairs and to_list(m) gives the values (also values, below, which reads as Map's own the way keys does). For the pairs themselves, use entries.

Conventions:

  • get takes the value to fall back to, so a miss is never a surprise.
  • key types never collide: {a: 1} and {"a": 1} are different maps.
  • a predicate always takes the (key, value) pair and comes last: filter and reject screen the whole map with one.
  • merging is the ++ operator, with the right map winning a clash; reach for merge_with when a clash should combine instead of overwrite.
  • equality ignores order: {a: 1, b: 2} == {b: 2, a: 1} is true.

fn merge_with(a, b, f) ¶

Merges a and b like ++, except a key present in both is resolved by f(a_value, b_value) instead of b's value silently winning. A key present in only one map keeps its value untouched.

Map.merge_with({a: 1, b: 2}, {b: 10, c: 3}, do x, y -> x + y)
# == {a: 1, b: 12, c: 3}

the base map
b
the map to merge in
f
a lambda (a_value, b_value) resolving a colliding key

Returns: a new Map, a and b merged with f deciding collisions

fn map_values(map, f) ¶

fn map_keys(map, f) ¶

A new map with each key replaced by f applied to it. Values are kept; if f maps two keys onto one, the later pair wins.

Map.map_keys({1: :a, 2: :b}, do k -> k * 10)   # == {10: :a, 20: :b}
map
the map to walk
f
a lambda from a key to its replacement

Returns: a new Map with mapped keys and the same values

fn map_entries(map, f) ¶

A new map built by replacing each pair with the (key, value) tuple f returns for it.

map
the map to walk
